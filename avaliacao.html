8,0 PONTOS Critérios Principais da Pipeline
✓
Ingestão de dados
Simulador gera dados reais de GPS (300 ônibus, 20 linhas), catracas (18 estações VLT) e bikes. Registros em JSON imutável com timestamp UTC. Inclui lógica de outliers (velocidade > 100 km/h → quarentena).
pipeline_simples.py → ingestao() data/bronze/gps/*.json data/bronze/catracas/*.json
✓
Armazenamento — Data Lake Medallion
Camada Bronze (JSON raw) → Silver (Parquet Snappy, schema validado) → Gold (DuckDB, tabelas analíticas). Sem Docker: armazenamento local com estrutura padronizada. DuckDB é o engine único.
data/bronze/ data/silver/*.parquet data/gold/urbanflow.duckdb
✓
Transformação — Bronze → Silver → Gold
bronze_to_silver(): DuckDB SQL lê JSON, valida schema, descarta outliers para quarentena, grava Parquet Snappy comprimido.
silver_to_gold(): Cria tabela kpi_operacional (velocidade média, OTP, semáforo) e agg_demanda (entradas, saídas, receita por estação).
pipeline_simples.py → bronze_to_silver() pipeline_simples.py → silver_to_gold()
✓
Orquestração — Execução encadeada com controle de dependências
Função main() orquestra as etapas em sequência com tratamento de erro e log de tempo. Arquivo orchestration/dags/urbanflow_pipeline.py contém DAG Airflow completo para ambiente produtivo.
pipeline_simples.py → main() orchestration/dags/urbanflow_pipeline.py
✓
Consumo / Serving — Dashboard + Queries analíticas
serving(): queries SQL diretas no Gold e relatório impresso no terminal.
gerar_dashboard(): lê o DuckDB Gold e gera dashboard.html com 4 gráficos interativos (Chart.js), hospedado no GitHub Pages.
pipeline_simples.py → serving() dashboard.html (GitHub Pages)
→ Abrir Dashboard
